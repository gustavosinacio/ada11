# Ada11 — Gym Tracker

Personal training-session tracker. Universal app: iOS, Android, and Web from one Expo Router codebase. Backend on Supabase (Postgres + Auth + RLS).

> Detailed architecture, decisions, and onboarding context live in [`docs/`](./docs/README.md). New agents/contributors should read `docs/README.md` first.

## Stack

- **Frontend**: Expo SDK 54, React 19, React Native 0.81, Expo Router 6, TypeScript strict.
- **Styling**: NativeWind v4 (Tailwind for RN).
- **Data**: Supabase JS client (auth-aware queries, RLS-protected).
- **Schema**: Drizzle ORM (TypeScript schema → Postgres migrations).
- **Server state**: TanStack Query, persisted to AsyncStorage.
- **Forms**: react-hook-form + zod.
- **Icons**: lucide-react-native.
- **Auth**: Supabase Auth (email + password, Google, Apple).

## Getting started

### 1. Install dependencies

```bash
npm install
```

(`.npmrc` sets `legacy-peer-deps=true` — needed because some libs ship outdated peer ranges.)

### 2. Create a Supabase project

1. Sign up at [supabase.com](https://supabase.com) and create a new project.
2. Copy `.env.example` to `.env.local` and fill in:
   - `EXPO_PUBLIC_SUPABASE_URL` (Project Settings → API)
   - `EXPO_PUBLIC_SUPABASE_ANON_KEY` (Project Settings → API)
   - `SUPABASE_SERVICE_ROLE_KEY` (Project Settings → API; keep server-side only)
   - `DATABASE_URL` (Project Settings → Database → Connection string → URI)

### 3. Apply migrations

```bash
# Generate the schema migration from src/db/schema.ts
npm run db:generate

# Apply both 0000 (schema) and 0001 (RLS + seed) to Supabase
npx supabase link --project-ref <your-project-ref>
npm run db:push
```

### 4. Verify RLS

```bash
npx tsx tests/rls.test.ts
```

Should print `✅ RLS test passed`.

### 5. Run

```bash
# Web (browser)
npm run web

# iOS Simulator
npm run ios

# Real iPhone (free provisioning, weekly cert renewal)
npx expo run:ios --device
```

## Locked architecture decisions

1. **Auth**: Supabase Auth — email/password, Google, Apple. Email verification on. 8-char min password.
2. **Data**: Drizzle (schema source of truth) + Supabase JS client (runtime queries) + RLS enforced in Postgres. `user_id` denormalized on every table; uniform `auth.uid() = user_id` policies.
3. **Sync**: online-first with TanStack Query persistence. Offline-first sync engine deferred to v2 if needed.
4. **Hosting**: EAS Hosting for the web build. Supabase for backend services. `app/api/*` reserved for future Expo Router API routes.
5. **Schema**: weight × reps × optional RPE. Routines optional. Per-user exercise library, pre-seeded with ~30 lifts on signup. Set type (`warmup` / `working` / `dropset`) with `parent_set_id` for drop chains. `target_rest_seconds` on routine entries for the rest timer.
