## Prompt / schema adjustments to fold back

1. **Make Discovery's kernel-inventory step exhaustive-by-construction for "apply X everywhere" features.** The single highest-leverage fix this run: when the feature is "change one predicate at every site," the Discovery contract should REQUIRE the close-the-set grep (`grep -rn '\* r' / 'parseFloat(.*weight' / 'weight ? parseFloat'` across `app/` + `src/`) + a hit→inventory-row table + an explicit "no N+1th site exists, and here are the non-volume hits I excluded" line — the exact proof the Validator had to produce in round 2 (`validation-v2.md:28-53`). Discovery owes that closed-set proof first. This would have caught both `weekVolumeKg` (a headline reduce that doesn't read like a kernel) and the second `groupSessionVolumes` caller at Discovery time, saving the no-go round. This is also the same root as the prior-run Discovery miss (greppped the project but missed the framework's own auto-pop) — both were "thorough-looking but not exhaustive-by-construction."
2. **Distinguish "surface" from "kernel" from "call site" in the Discovery template.** A single surface can host multiple kernels; a single kernel can have multiple call sites. Discovery's surface table should answer, per surface, (a) is this the only kernel here? and (b) how many distinct call sites does each kernel have? Both questions, answered with grep, close the MAJ-1/MAJ-3 gap.
3. **For e2e test data, the Implementer must resolve seed names against the live canonical source (`0011`, `user_id IS NULL`), not a per-user trigger seed.** `pickCanonicalExercise` requires a canonical row; the round-1 "Pull-up" defect came from citing the wrong seed migration. A one-line note in the Implementer brief ("verify any `pickCanonicalExercise(admin, NAME)` against the live canonical catalog, not `0004`") would prevent the recurrence.
4. **The pre-existing `chart-scroll-week-selector.spec.ts` date-label failure should be filed separately.** It is unrelated to this feature (proven via baseline stash), and the spec expects `m/d` "5/25" while the app now renders `dd/mm` "25/05" (per commit `5a2382b`). Track as a standalone fixture-drift ticket.
