## Issues found

### Blockers

### Majors
- **[MAJ-1]** `design-v1.md:206-207` (e2e tests 5b + 6): **The integer-count teeth assertion targets a chart surface NEVER exercised in this 14-spec e2e suite, and test 6 (the ONLY end-to-end proof of LOCKED Invariant D) has no non-SVG fallback.** The y-axis tick labels are `react-native-svg` `<SvgText>` → SVG `<text>` DOM nodes on web (`multi-series-chart.tsx:121-132`). Every existing numeric e2e assertion (`week-drill-down.spec.ts:190` `"2,500 kg"`, `weekly-volume-strip.spec.ts:306` `"500 kg"`, etc.) targets a regular `<Text>` card/strip node — **zero** tests query `MultiSeriesChart` SVG tick text, and the chart exposes NO `testID`/`accessibilityLabel` handle (`multi-series-chart.tsx` — grep: none). Compounding it, the y-ticks are fractional-rounded: for 3 sets, `range=3` ⇒ ticks `(3/4)*i = 0,0.75,1.5,2.25,3` → `Math.round` → `0,1,2,2,3` (the design's rounding at `:182`), so the literal "3" appears once at the top but "2" appears twice; for the dropset test the working-only top tick is "2" (`range=2` ⇒ `0,0.5,1,1.5,2` → `0,1,1,2,2`). So `getByText("2")` is ambiguous and `getByText("3")` may or may not resolve under react-native-web 0.21. Test 5 still has the header-swap floor (teeth, precedented), but **test 6's entire teeth rest on this untested+ambiguous surface** — if `getByText` cannot see SVG `<text>`, test 6 false-greens (count 0 = "absent" trivially) or errors. Suggested fix: (a) re-frame test 6 to assert the NAIVE-count value `"3"` is **ABSENT** in sets mode after seeding 2 working + 1 dropset (absence of the wrong value is unambiguous and is the actual divergence signal), AND keep a positive anchor (the "Weekly hard sets per muscle" header) awaited first so absence-because-correct is distinguished from absence-because-not-loaded; OR (b) the Implementer adds a `testID` to the chart's peak/top-tick so the Tester can assert a stable handle; AND (c) require the Tester to PROVE the assertion fails when the dropset is wrongly counted (teeth) — without that proof the e2e is decorative. Unit case 4 already covers Invariant D deterministically, so this is test-side, recoverable, and does not touch the production seam — major, not blocker.

### Minors
- **[MIN-1]** `design-v1.md:206`: the "absent after swap" target is the wrong literal. `formatVolume(500, "kg")` renders **`"500 kg"`** (with the `" kg"` suffix + `toLocaleString` — `units.ts:33-40`), NOT bare `"500"`. `getByText("500")` (non-exact) would still match `"500 kg"` and false-fail; the absence assertion must target `"500 kg"` (or use `{exact:true}` on `"500"`, which then never matches because the rendered string is `"500 kg"`, making the absence trivially-true and toothless). Suggested fix: assert absence of `"500 kg"`; assert presence of the bare sets value with `{exact:true}`.
- **[MIN-2]** `design-v1.md:15,186`: the existing tonnage suite has **13** `it()` cases, not 14 (count: `test.ts` lines 89,100,125,155,176,212,241,260,282,306,354,400,437). Cosmetic; the "stay green unchanged" claim holds regardless. Suggested fix: say "all 13 existing cases".
- **[MIN-3]** `design-v1.md:207` (e2e test 6 seed): the existing `seedFinishedSession` (`weekly-muscle-volume.spec.ts:89-127`) inserts `workingSets` rows ALL with one `set_type` (hardcoded `"working"` at `:119`). The design's parameterization (`setType?` defaulting `"working"`) is sound but yields ONE `set_type` per call — so "2 working + 1 dropset in the same week" requires TWO `seedFinishedSession` calls (working×2 + dropset×1) into the same ISO week, which the design's prose does not spell out. Suggested fix: note the two-call seed shape so the Implementer doesn't try to mix set types in one call.
- **[MIN-4]** `design-v1.md:201-202` (Invariant-T deepEqual anchor): partially redundant with the existing W-0 case (`test.ts:306-352`), which already asserts `windowStartMs:undefined === no-param` byte-for-byte on a multi-week multi-muscle fixture. The new frozen-model deepEqual is additive and harmless (it pins absolute numbers, not just param-equivalence), so keep it — just acknowledge the overlap. No action required.

## Items I explicitly assessed and found SOUND

- **Scaffold vs sibling-presenter choice (claim "Also assess").** The shared-scaffold + thin-wrapper shape is the right call: it keeps the wrapper's public signature byte-identical (the 16 unit-test call sites bind it), routes both metrics through one `muscles[0]` attribution so feature #2 lands once (U6), and the sibling presenter correctly OMITS `measurements` so the section never wires bodyweight into the sets path (closes the U1 trap by signature). The `WeeklyMuscleHardSetsModel = WeeklyMuscleVolumeModel` alias is fine — the chart consumes `{weeks, series:[{key,values:number[]}]}` identically; only `formatValue` interprets the units.
- **Invariant T preservation including memoization.** The design's "compute-`resolveBw`-then-`include`" order under `needsLoad:true` reproduces today's "compute-`w,r`-then-guard" exactly (`:120-123`); the per-`session_id` bw cache populates in the same row order (rows are not reordered), so no hidden divergence. Structurally, the sets path CANNOT re-acquire bodyweight: `resolveBw` is gated behind `needsLoad`, and the sibling signature has no `measurements` arg to feed it.
- **`metric` in memo deps / branch-not-compute-both.** Branching the single memo on `metric` (`:141`) is correct and cheaper than compute-both; `measurements` staying in deps is harmless on the sets branch (not read). The `visible`-Set sharing + the R-4 reseed edge (a muscle present in tonnage but all-dropset in sets flips `seriesKeysSig` → reseed all-on) is consistent with the existing refetch-reseed (`:71-75`), not a new failure mode.
- **No N+1 surface / no fan-out.** Discovery's close-the-set holds: the hard-sets-per-muscle/week metric is genuinely new (no other weekly-per-muscle set-count display), and because the SELECT is unchanged the 6 `useLifetimeWeeklyVolume` consumers are untouched. This feature does NOT thread a field through a shared kernel (it abandons `effectiveWeightKg`), so the input-builder close-the-set lesson does not apply.
- **Platform / `aria-checked`.** The design correctly asserts on swapped TEXT + active class, not `aria-checked` (web does not map `accessibilityState`, `weekly-muscle-volume.spec.ts:280-285`). Sound.
