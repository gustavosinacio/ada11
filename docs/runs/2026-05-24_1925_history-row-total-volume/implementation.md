## Deviations from design

- **Test fixture builder for `WeeklyVolumeRow` — `??` vs `in` check (load-bearing)**: In `tests/unit/group-session-volumes.test.ts`, the `mkRow` fixture builder ended up needing an `"completed_at" in overrides` check (not `??`) for the `completed_at` field. Reason: one of the design's test cases ("excludes a row with null completed_at, even if server pre-filters") passes an explicit `null` to verify the kernel's guard. `??` would silently coerce that `null` to the default ISO string, defeating the assertion (the test originally failed with `expected 500, received 1000`). Switched to a property-presence check so explicit `null` survives. Doesn't change the surface of the design; it's a test-utility-level correction.
- **History list — destructure naming**: Aliased `data: weeklyVolumeData` in `app/(app)/history/index.tsx` to avoid shadowing the existing `data` destructure from `useSessions()` in the same scope. Equivalent to design intent (expose the lifetime cache's data); the alias is the minimal-change way to expose `data` without renaming `useSessions()`'s destructure.
- **`history/[id].tsx` `totalSets` count semantics**: Implemented exactly as designed (`.filter(s => s.completed_at != null && s.set_type !== "warmup").length`). Calling this out explicitly because it changes the visible "N sets" count for finished sessions that contained warmup or unchecked rows (warmups and drafts previously counted; now they don't). This is the correctness improvement called out in design Riscos under "UX regressions (`history/[id]` detail header)". Flagged for Tester regression on a session with known warmup sets.

## Notes for Reviewer / Tester

- **Cross-surface number consistency (the prompt's load-bearing claim)**: every aggregate volume readout in the History flow — list row, week drill-down row, detail header — now routes through `sumLiveVolume`. The same kernel already powers the live session header, verdict screen, and per-exercise progress chart. A regression in any one surface will cascade visibly. The `tests/unit/session-header-total-volume.test.ts:232-273` "cross-screen parity" block is the contract test for this guarantee.
- **Visible-number change on history-detail header (MEDIUM-risk)**: The old `history/[id].tsx` reduction was non-canonical (counted warmups, no `w > 0 && r > 0` guard, used `formatWeight` which rendered `"12345.0 kg"`). The new kernel-backed total will read *lower* for any historical session that contained warmup volume. This is a correctness improvement, but Tester should compare the History list row, the detail header total, and the verdict screen total for the same warmup-heavy session — all three must now match digit-for-digit.
- **In-progress session row**: The lifetime cache excludes `ended_at IS NULL`, so `map.get(id)` returns `undefined` for the active session row. The presenter hides the volume slot; the existing orange "In progress" tag continues to render. Tester: confirm the in-progress row shows date · duration only, plus the orange tag — no `0 kg` text and no `· kg` label.
- **Cold-cache flicker (LOW-risk)**: On first paint of the History tab, rows render without the volume slot until `useLifetimeWeeklyVolume()` resolves. No layout shift (the `<Text>` simply grows at the end of line 2). Same staleness model as the existing `<WeeklyVolumeStrip>` on the same screen.
- **E2E selector unchanged**: `tests/e2e/exercise-progress-ia.spec.ts:298` uses `/·\s*\d+m\b/` which anchors on the duration token alone; the appended volume slot doesn't break it. Only the comment was updated to reflect the new row shape.
- **Kernel widening is structurally compatible**: `sumLiveVolume`'s new `Pick<SetRow, "completed_at" | "set_type" | "weight" | "reps">[]` signature accepts every existing `SetRow[]` caller (verified across `session-verdict-math.ts`, `session-header.tsx`, the existing unit test, and the local self-call inside `volume-target.ts`). `tsc --noEmit` confirmed zero callsite breakage.
